## CORRECCIONES al TRASPASO.md anterior (importantes)

1. **Tests del frontend usan VITEST, no Jasmine.** El traspaso viejo decía "jsdom+TestBed,
   NUNCA vitest"; en la práctica `npx ng test` arranca **Vitest**. Consecuencia real:
   los matchers deben ser de Vitest: usar `expect(x).toBe(true)` (NO `toBeTrue()`),
   `toEqual`, `toContain`, `toBeInstanceOf`. Comando que funciona:
   `npx ng test --watch=false --include="<ruta-al-spec>"`.

2. **JDK: hay que compilar con JDK 21, aunque la máquina tenga JDK 25.** Con JDK 25,
   Lombok 1.18.34 rompe la compilación (`java.lang.ExceptionInInitializerError:
   com.sun.tools.javac.code.TypeTag :: UNKNOWN`). Fijar `JAVA_HOME` al JDK 21 antes
   de cualquier build de backend (ver comandos abajo).

3. **`-o` (offline) de Maven solo funciona si `.m2` ya está poblado.** En una máquina
   nueva, el PRIMER build/test de backend debe ser ONLINE (sin `-o`) para descargar
   plugins (incl. `surefire-junit-platform`). Después ya se puede usar `-o`.

4. **La terminal de la sesión duplica el eco de caracteres** y a veces reporta exit
   code -1 aunque el comando SÍ corre. Estrategia fiable: volcar salida a un archivo
   `_*.txt`/`_*.log` y leerlo. Estos temporales están en `.gitignore`.

## LO NUEVO DE ESTA SESIÓN: Bloque enterprise "Contabilidad Electrónica SAT (Anexo 24)"

Feature full-stack (backend + frontend) que agrega la Contabilidad Electrónica del SAT
al módulo `contabilidad` ya existente. Spec en
`.kiro/specs/contabilidad-electronica-sat/` (requirements + design + tasks).

**Genera y descarga** (no envía al Buzón Tributario; eso se hace en el portal del SAT con
el XML descargado):
- **Catálogo de cuentas XML** (esquema `.../ContabilidadE/1_3/CatalogoCuentas`).
- **Balanza de comprobación XML** (`.../BalanzaComprobacion`).
- **Pólizas del periodo XML** (`.../PolizasPeriodo`).

### Migración nueva
- **V71** `V71__contabilidad_electronica_sat.sql`. Backend pasó de **v70 a v71**.
  - Columna `codigo_agrupador_sat VARCHAR(10)` en `cuenta_contable` (con RLS heredada).
  - Tabla `codigo_agrupador_sat_catalogo` (DATO DE PLATAFORMA, SIN RLS): catálogo oficial
    del Apartado B del Anexo 24, sembrado con ~98 códigos (niveles 1 y 2, naturaleza D/A).
    Es AMPLIABLE en migraciones futuras.
  - Permisos nuevos (idempotentes, enlazados al rol `contabilidad` =
    `a0000000-0000-0000-0000-00000000000b`): `contabilidad_electronica:leer`,
    `contabilidad_electronica:exportar`, `cuenta_contable:actualizar`.

### Backend (submódulo nuevo `com.dessti.crm.contabilidad.electronica`, hexagonal)
- `domain/CodigoAgrupadorSat` (entidad del catálogo de plataforma, sin RLS).
- `domain/xml/` generadores PUROS con StAX: `GeneradorCatalogoXml`, `GeneradorBalanzaXml`,
  `GeneradorPolizasXml`, `XmlUtil` (importe a 2 decimales) + `EncabezadoSat`.
- `domain/modelo/` records de entrada: `CuentaCatalogoSat`, `RenglonBalanzaSat`,
  `PolizaSat`, `TransaccionSat`.
- `application/ServicioContabilidadElectronica`: previews + exportaciones. La balanza se
  DERIVA de las pólizas ya persistidas reutilizando
  `ReportesContablesRepository.agregarSaldosPorCuenta(desde,hasta)`: saldo inicial =
  agregado ANTES del periodo con signo por naturaleza; debe/haber = movimientos del periodo;
  saldoFin = saldoIni ± delta. 422 si la balanza no cuadra al exportar; 422 si no hay cuentas
  amarradas al exportar catálogo.
- `application/ServicioAmarreAgrupador`: amarra una cuenta a un código agrupador (valida
  contra el catálogo, 422 si no existe; audita). Vive en `electronica` (no en `polizas`)
  para evitar dependencia circular: **electronica → polizas**, nunca al revés.
- `application/CatalogoAgrupadorSatPort` + adapter; `DatosFiscalesEmpresaPort` + adapter
  (RFC del tenant vía `EmpresaRepository.findById`).
- REST:
  - `GET /contabilidad/codigos-agrupadores-sat?q=` (perm `contabilidad_electronica:leer`).
  - `PATCH /contabilidad/cuentas-contables/{id}/codigo-agrupador` (perm `cuenta_contable:actualizar`).
  - `GET /contabilidad/contabilidad-electronica/{catalogo|balanza|polizas}/preview` (leer).
  - `GET /contabilidad/contabilidad-electronica/{catalogo|balanza|polizas}/xml?anio=&mes=`
    (exportar) → descarga `application/xml` con nombre `<RFC><AAAA><MM>{CT|BN|PL}.xml`.
- Se extendió `CuentaContable` (campo `codigoAgrupadorSat` + `amarrarCodigoAgrupador`),
  `CuentaContableDto` (ahora incluye `codigoAgrupadorSat`; OJO: cambió el orden del record),
  `CuentaContableRepository.listarTodasOrdenadas(activa)` y
  `PolizaContableRepository.listarPorPeriodo(desde,hasta)`.
- Todos los endpoints con doble gating `@autorizador.moduloHabilitado('contabilidad') and
  @autorizador.tiene(...)`.

### Frontend (Angular, dentro de `features/contabilidad`)
