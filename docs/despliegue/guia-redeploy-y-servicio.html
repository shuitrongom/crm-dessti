Actualizacion (redeploy) + backend como servicio (nssm)

Como actualizar el CRM en el servidor con una version nueva de backend (jar) y frontend, y dejar el backend como servicio de Windows para que sea estable.

Acceso: https://dessti-aplicaciones.ddns.net:8056

Resumen de esta actualizacion

  • Cambian backend Y frontend (integracion de bloques, lead social, indicadores comerciales, favicon).
  • NO hay migraciones nuevas de base de datos. La ultima sigue siendo la V63 (ya aplicada). Flyway solo validara el esquema al arrancar; no ejecutara SQL. No debes correr ningun SQL.
  • El super_admin admin@dessti.com creado antes sigue existiendo; no se recrea.
  • Se aprovecha para dejar el backend como servicio de Windows (nssm): arranque automatico y reinicio ante fallos.
Artefactos a copiar (desde tu equipo de build)
#OrigenDestino en el servidor
1backend\target\crm-0.0.1-SNAPSHOT.jarC:\apps\crm\backend\
2frontend\dist\frontend\browser\* (el CONTENIDO)C:\inetpub\wwwroot\crm\

Instalar nssm (una sola vez)

nssm convierte el backend Java en un servicio de Windows robusto. Es un unico ejecutable.

# Descargar y colocar nssm.exe en C:\tools
Invoke-WebRequest -Uri "https://nssm.cc/release/nssm-2.24.zip" -OutFile "$env:USERPROFILE\Downloads\nssm.zip"
Expand-Archive "$env:USERPROFILE\Downloads\nssm.zip" -DestinationPath "$env:USERPROFILE\Downloads\nssm" -Force
New-Item -ItemType Directory -Force -Path C:\tools | Out-Null
Copy-Item "$env:USERPROFILE\Downloads\nssm\nssm-2.24\win64\nssm.exe" "C:\tools\nssm.exe" -Force
"nssm listo en C:\tools\nssm.exe"
Si ya tienes nssm Omite este bloque y usa la ruta donde lo tengas.

Pasos del redeploy

Paso 1 Detener el backend actual

Si el backend corre arrancado a mano (proceso java):

Get-CimInstance Win32_Process -Filter "Name='java.exe'" |
  Where-Object CommandLine -like '*crm-0.0.1-SNAPSHOT.jar*' |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
"Backend detenido"

Si ya existiera el servicio CRM-Backend (de una vez anterior): Stop-Service CRM-Backend.

Paso 2 Reemplazar el jar del backend

Copia por RDP el nuevo crm-0.0.1-SNAPSHOT.jar a C:\apps\crm\backend\ (sobrescribe). Verifica:

(Get-Item C:\apps\crm\backend\crm-0.0.1-SNAPSHOT.jar).LastWriteTime  # debe ser de hoy

Paso 3 Reemplazar el frontend

Copia el CONTENIDO de frontend\dist\frontend\browser\* a C:\inetpub\wwwroot\crm\ (sobrescribe).

NO sobrescribas el web.config del servidor En el servidor el web.config tiene una correccion (se le quito el bloque <caching>). Al copiar, si Windows pregunta por web.config, conserva el del servidor (omite ese archivo). 
(Get-Item C:\inetpub\wwwroot\crm\index.html).LastWriteTime   # de hoy
Test-Path C:\inetpub\wwwroot\crm\web.config                  # True
Test-Path C:\inetpub\wwwroot\crm\favicon.svg                 # True

Paso 4 Instalar/actualizar el backend como servicio (nssm)

En lugar de arrancarlo a mano, lo dejamos como servicio. El script lee parametros.ps1 (ya configurado con las claves de produccion).

cd C:\apps\crm\deploy
Unblock-File .\instalar-servicio-backend.ps1
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process -Force
.\instalar-servicio-backend.ps1 -Metodo nssm -NssmPath C:\tools\nssm.exe

El script (idempotente) detiene/recrea el servicio CRM-Backend, lo pone en arranque automatico con reinicio ante fallos, y lo inicia.

Paso 5 Verificar

Get-Service CRM-Backend                     # Status = Running
Start-Sleep -Seconds 50
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8080/api/v1/actuator/health" -TimeoutSec 15

Debe responder 200 con {"status":"UP"}. Revisa el arranque en C:\apps\crm\logs\backend-stdout.log.

Paso 6 Prueba de extremo a extremo

Abre https://dessti-aplicaciones.ddns.net:8056 (Ctrl+F5). Inicia sesion como super_admin y verifica que carga y que las pantallas conectadas funcionan (ficha 360 del cliente, canal en oportunidades, vincular conversacion, indicadores en estrategia/inicio).

Checklist

  • Backend anterior detenido.
  • Jar nuevo en C:\apps\crm\backend (fecha de hoy).
  • Frontend nuevo en C:\inetpub\wwwroot\crm (index.html de hoy; web.config conservado).
  • Servicio CRM-Backend en estado Running (arranque automatico).
  • Health http://127.0.0.1:8080/api/v1/actuator/health = 200.
  • La app carga en https://dessti-aplicaciones.ddns.net:8056 y el login funciona.
  • NINGUN SQL ejecutado (no hay migraciones nuevas).

Actualizaciones futuras (resumen rapido)

Con el servicio ya instalado, actualizar es aun mas simple:

Stop-Service CRM-Backend
# reemplazar el jar en C:\apps\crm\backend\
# reemplazar el contenido del frontend en C:\inetpub\wwwroot\crm\ (conservar web.config)
Start-Service CRM-Backend
Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:8080/api/v1/actuator/health"
Respaldo Solo cuando una actualizacion incluya migraciones nuevas conviene respaldar la BD con pg_dump antes. Esta actualizacion NO trae migraciones.
